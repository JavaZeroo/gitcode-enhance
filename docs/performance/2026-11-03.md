# 2026-11-03 内存与动态加载优化（发布前记录）

以下是开发过程记录，对应改动已纳入 v0.3.4；渠道状态见[发布记录](../releases/v0.3.4.md)。保留各阶段原始版本和验证数量，不将后续发布视为新增实页测量。

后续已完成 CPU 时间线、调用栈、开关/单变量对照和缓存生命周期测量，见 [profiling 报告](2026-11-03-profiling.md)。下方保留早先探索性记录，不作为新修复的效果证据。

## 已实施

- 差异索引只保留文件元数据和可搜索行，去掉原始 diff；缓存中的快照只保留提交与文件总数。
- 关闭搜索清除结果、面板全局回调和局部索引引用；保留一分钟的复用缓存，随后释放。路由切换立即释放缓存。超过一分钟再打开需要重建索引。
- 离开 diff 页面解除评审工具回调及文件 DOM 引用。
- 去干扰初次扫描全页，后续只扫描新加入的子树；队列超过 128 个节点时合并为一次全页扫描，取消任务时清空队列。
- 拦截记录及去重集合最多保留最近 100 个不同 URL，防止长时间使用时无限增长。旧 URL 被淘汰后再次出现可重新计入。
- 保留上一轮同一折叠按钮不重复自动点击的改动。

## 验证

22 项 Node 回归测试通过，构建成功。新增测试覆盖原始 diff 不再留在索引、缓存过期、日志上限、20 批动态插入不再触发全页扫描以及清理待执行任务。

Edge 登录态、用户当前 aggressive 档位。PR `Ascend/torchtitan-ascend/pull/97/diffs` 刷新后索引 2/2 文件，搜索 Qwen 返回 40 条匹配行，关闭搜索后面板移除。推荐首页 `/?p=seo` 刷新后内容正常。用户普通 `/` 首页设置会重定向到 `/dashboard/pulls`，不混入推荐首页样本。

## 未解决与下一步

- 本轮证明减少数据保留和全页扫描，尚未证明整页加载加速或降低多少 MB。
- 讨论页回复框晚出现仍需独立复现；不强制撑高编辑器、不缓存权限或 PR 状态接口。
- 后续对推荐首页、工作台、PR 讨论、长 diff 分别做同一会话交替版本、多轮冷/热缓存采样；以首屏、编辑器可用、搜索可用和回收后的堆为独立指标。
- 站点复用同一折叠按钮加载下一批时，当前策略需要手动继续，仍需实页覆盖。
